### Отчет по лабораторной работе №4

 1. Модель детектора

В лабораторной работе была создана модель детекторной системы для регистрации распада π⁰-мезона. Детектор состоит из трековой системы, калориметра и соленоида. Трековая система определяет траектории заряженных частиц с помощью кремниевых слоев. Калориметр регистрирует энергию фотонов и электрон-позитронных пар, используя чередующиеся слои свинца и пластика. Соленоид создаёт магнитное поле, которое искривляет траектории заряженных частиц, позволяя различать электроны и позитроны.

 2. Логические объёмы

Структура логических и физических объёмов собрана внутри базового объёма **detectorLogic**. В него входят: трековая система с кремниевыми слоями, где ячейкам назначен **TrackerSensitiveDetector**; калориметр, состоящий из сегментов со свинцовым и пластиковым слоями, при этом **CalorimeterSensitiveDetector** назначен на пластиковые слои этих сегментов; а также соленоид **magnetLogic**, которому чувствительный детектор не назначается.

 3. Генерация распада π⁰

Для моделирования распада π⁰ был создан отдельный файл **PiDecayGenerator**. В нём реализованы два канала распада:  
- для π⁰ → γγ направления фотонов задаются с помощью генератора случайных чисел 
- для π⁰ → e⁺e⁻γ распределение трёх частиц в фазовом пространстве генерируется с использованием генератора фазового пространства **TGenPhaseSpace**.  

Ограничение на угол  θ от 0.1 до π−0.1  накладывается в **MyPrimaryGeneratorAction** при генерации первичных частиц:  
- для распада γγ проверяется только угол первого фотона (второй фотон автоматически направлен обратно)
- для распада e⁺e⁻γ проверяются углы всех трёх частиц, каждая из которых должна попасть в диапазон 0.1 < θ < π−0.1.  

Если распад π⁰ не используется, задаются отдельные первичные частицы: электрон и фотон, движущиеся вдоль оси z.

 4. Регистрация данных

В трековом детекторе фиксируются координаты пролёта и время прохождения первичных частиц, при этом учитываются только первичные частицы, не являющиеся фотонами. Калориметр фиксирует энергию, выделяющуюся в каждом сегменте, при этом данные суммируются отдельно для левого и правого блоков детектора. Все данные сохраняются с помощью **G4AnalysisManager** в ntuple внутри ROOT-файла, что позволяет далее проводить анализ распределений и гистограмм для каждого слоя трекового детектора и каждого сегмента калориметра.
